## 二、需要你提供的官方源文件（关键阻塞）

每条新法需一份**官方 .doc / .docx**（主席令 / 常委会公报版）。来源优先级：
1. `flk.npc.gov.cn` 对应法律页面 → 下载公报版全文（最权威）。
2. `gov.cn` 法律频道。
3. 你本地已有权威副本（如税务师教材附赠法条提取件）。

| 法律 | law_code | 需提供的有效版本 | 现行生效节点 |
| --- | --- | --- | --- |
| 中华人民共和国企业所得税法 | `EIT_LAW` | 2007 主席令63号 + **2018 修正版**全文 .doc | 2018 修正后文本（税率25%等） |
| 中华人民共和国个人所得税法 | `IIT_LAW` | 2018 主席令9号（含专项附加扣除）全文 .doc | 2019-01-01 施行，现行有效 |
| 专利法（补强） | `PATENT_LAW` | 2020 修正版（2021-06-01 施行）全文 .doc | 现行有效 |

> ⚠️ **必须给"现行有效"版本官方文本**。旧法文本会被 `extract.py` 的 as_of 门禁判
> `TEMPORAL_DEPRECATED`，节点无法进入判分面。增值税法就是前车之鉴（as_of 必须 ≥ 2026-01-01）。

**你只需做两选一**：
- (A) 把上面 3 个 .doc 文件丢进项目（或发我路径），我直接 `textutil`/`unzip` 解析；或
- (B) 确认我可从 `flk.npc.gov.cn` 下载对应公报版（需联网），我自行抓取。

## 四、执行协议（复用 `KB_EXPANSION_PLAN.md` §五，防漂移标准动作）

每落地一部新法，严格按序：
1. **登记索引**：`laws_index.json` 增 law 条目（`name`/`aliases`/`type`/`status`/
   `effective_date`/`source_url`/`source_accessed_at`）。**不写 `deprecated_aliases`**（单源不变量）。
2. **登记来源**：`build_statute.py` 的 `LAW_SOURCES` 增 `law_code → flk.npc.gov.cn` 链接。
3. **粘贴条文**：官方条文**粘贴**进 `SEED`（绝不手打；`effective_date` 对齐现行版）。
4. **生成 + 校验**：`python -S -m knowledge_base.build_statute build` → `... validate`。
5. **专家签名**：`python -S -m knowledge_base.verify_kb` 走查 → 写入 `verifications.json`
   （每节点 `verified`，**须你本人签署**，Agent 不代签法律结论）。
6. **测试同步**：`tests/test_kb_coverage.py` 抬高 `MIN_TOTAL` / `MIN_NODES[law_code]`；
   补该法覆盖断言；全量 `python -S -m unittest discover` 保持绿灯。
7. **报告刷新**：`python -S -m benchmark.run --offline --input answers.jsonl`。
8. **提交**：KB 变更与基准代码变更**分开 commit**（便于审阅），每法一 commit。
