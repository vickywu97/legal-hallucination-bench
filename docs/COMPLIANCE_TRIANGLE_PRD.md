# 合规三角（Compliance Triangle）— 产品需求文档（PRD）

> 状态：Phase 0（规划确认） · 关联仓库：`legal-hallucination-bench`（评测基准 / KB / verify 引擎）
> 作者：Vicky Wu（律师 / 税务师 / 专利代理师） · 定位：AI 法律产品经理作品集第二大件

---

## 1. 产品定义：什么是「合规三角」

「合规三角」= **企业三大合规支柱**，对应作者本人**三证合一**的稀缺资质：

| 支柱 | 合规域 | 对应资质 | 覆盖法律（复用 Bench KB） |
| --- | --- | --- | --- |
| 法律合规 | corporate / civil / criminal | 律师 | 公司法、民法典、刑法 |
| 税务合规 | tax | 税务师 | 企业所得税法、个人所得税法、增值税法、税收征收管理法 |
| 知识产权合规 | ip | 专利代理师 | 专利法（后续可扩展商标、著作权法） |

**护城河**：市面上没有任何竞品能同时覆盖这三个领域并由此**同一人**签字背书——
通用 AI 做不到逐字准确（Bench 已证明），单域律师做不到跨域交叉，而本产品的三证恰好填上了这个缺口。

## 2. 核心叙事闭环（作品集最强卖点）

> 「我先用量化基准 `legal-hallucination-bench` 证明了 AI 在法律引注上不可信
> （5 模型 HVI 50%–64.6%，且 EXACT 逐字合规率 8 域全为 0%）；
> 然后用**同一套 verify 引擎**构建了合规三角——让 AI 生成的每条法条引注都经过
> **存在性 / 时效性 / 内容匹配**三层校验，不过门禁的红框标出。」

这不是「我会用 AI」，而是「我知道 AI 哪里会出错，并且我能设计系统来防止这些错误」——
这是 AI 法律产品经理最核心的能力证明。

---

## 3. 产品定位

面向**企业法务 / 财税 / IP 人员**的合规检查助手：用户输入业务场景（自然语言），
系统生成跨三域的合规分析 + 法条引注，并输出带 **「引注已核验」徽章** 的结构化合规备忘录。
所有结论锚定已核验法条全文，杜绝「引用幻觉」。

**离线优先 / 零依赖**（与 Bench 一致，符合交付偏好）：可本地 `python run_demo.py` 跑通演示。

## 4. 技术架构（最大化复用 Bench 现有资产）

| 组件 | 现有资产（来源） | 复用方式 |
| --- | --- | --- |
| 法条 KB | `legal-hallucination-bench/knowledge_base/laws/statutes.jsonl`（2327 节点全文本，8 部法） | 直接读取（通过 `loader.load_laws()`），零修改 |
| 引注校验 | `benchmark/verify.py` → `resolve_article` + `content_diff` | 作为模块 import，输入 (law_name, article_no, candidate_text, as_of)，输出核验结果 |
| 时序陷阱 | `benchmark/extract.DEPRECATED_LAW_NAMES`（旧公司法 / 合同法 / 物权法等 10 部已废止法名） | 校验层自动识别「引用已废止法名」→ `TEMPORAL_DEPRECATED` |
| LLM 接入 | `scripts/generate_answers.py` 的 5 模型 OpenAI 兼容适配层 | 抽取为独立模块 `llm_adapter.py`，支持调用任一国产模型生成合规分析 |
| 输出模板 | `benchmark/pipeline.py` 的审计报告生成逻辑 | 改为输出「合规备忘录」（Markdown / HTML） |

**MVP 阶段唯一需要新增的代码（3 块）：**
1. 场景输入处理（用户自然语言描述）→ `prompt_template.py`
2. 合规分析 Prompt 模板（引导 LLM 结构化输出 + 标准引注格式）
3. 备忘录输出模板（Markdown / HTML，含 🟢🟡🔴 引注核验矩阵）

## 5. 关键设计

### 5.1 Prompt 设计（产品最关键环节之一）
引导 LLM：
- **结构化输出**：场景分析 / 涉及法域 / 具体条文 / 风险等级 / 建议措施；
- **标准引注格式**：`《法律名称》第X条`，便于引擎自动抽取；
- **只引现行有效法律**：否则触发 `NOT_FOUND` / `TEMPORAL_DEPRECATED`；
- 可选「逐字引用条文原文」或「概括适用」（概括会进入 🟡 待人工确认）。

### 5.2 校验层输出设计（🟢🟡🔴）
每条引注经核验后映射到三档徽章：

| 徽章 | 含义 | 触发条件（基于 verify 引擎） |
| --- | --- | --- |
| 🟢 已核验通过 | 法条**存在且在有效期内** | `resolve_article` 命中当前有效条文（`found=True` 且非已废止法名）；无引文文本或其内容匹配官方 |
| 🟡 待人工确认 | 法条真实，但**引述内容与官方有差异** | 命中真实条文，但 `content_diff` 显示非逐字（PARTIAL / FABRICATED，cov<1.0）→ 提示「引注真实，但措辞/但书可能与原文不符，请复核」 |
| 🔴 未通过核验 | 法条**不存在 / 已废止 / 张冠李戴** | `NOT_FOUND`（虚构或 relocated 条号）/ `TEMPORAL_DEPRECATED`（引用已废止法名）/ `UNVERIFIABLE`（未核验节点） |

每条核验附带 `note` 诊断说明（例：「该条文已于 2021-01-01 废止，现行有效为《民法典》第 584 条」）。

### 5.3 演示样例设计（内置 3–5 个场景，每个覆盖跨域交叉）
每个场景预置一份「含幻觉」的 LLM 回答，用以展示校验层如何捕获错误——直接呼应 Bench 的发现。

- **场景 1：员工股权激励**（公司法 + 个税法交叉）
- **场景 2：专利作价入股**（专利法 + 公司法 + 税法交叉）
- **场景 3：跨境技术许可**（专利法 + 税法交叉）
- **场景 4：企业研发费用加计扣除**（企税法 + 专利法交叉）
- **场景 5：公司对外担保决策**（公司法 + 民法典交叉）

## 6. 仓库决策：独立 Repo

**结论：独立仓库，名称 `compliance-triangle`。**

理由：
1. **边界清晰**：Bench 是评测工具，合规三角是产品应用，两个不同定位，独立仓库让招聘经理一眼看出「这是两个不同的作品」。
2. **依赖干净**：合规三角通过 `import` / 路径引用 Bench 的 KB 与 verify 引擎，不耦合代码。
3. **独立运营**：合规三角可有独立 Release / Issue / Star / 社区。
4. **作品集展示效果**：两个仓库并列在 GitHub 首页，比单仓库塞多个子目录更具视觉冲击力。

---

## 7. 与 Bench 的关系（不可动摇的架构原则）

- 合规三角**不存放法条**，只读 `legal-hallucination-bench` 的 `statutes.jsonl`（单一 ground truth）。
- 校验层**直接复用** `benchmark/verify.py` 的 `resolve_article` + `content_diff`，
  与 Bench 共用同一套「来源可信度门禁」（未核验节点永不作为判分基准）。
- Bench 扩法域（v1.4 行政法/程序法）后，合规三角**自动受益**，无需改代码。
