# KB 扩容规划 (Knowledge-Base Expansion Plan)

> 目标：把基准从「5 部法 / 99 节点」的 MVP 证据，升级为「15–20 部法 / 500–800 节点」、
> 足以对外声称"评测可信"的法律引注幻觉基准。
> 本文件是**规划**，执行按 §五 的协议逐法落地（每条新法走一遍质量门禁）。

---

## 一、现状盘点（2026-08-03）

| law_code | 名称 | 节点数 | 备注 |
| --- | --- | --- | --- |
| CIVIL_CODE | 民法典 | 26 | 总则/合同/侵权零散覆盖 |
| CRIMINAL_LAW | 刑法 | 27 | 总则 + 个别分则 |
| PATENT_LAW | 专利法 | 16 | 偏授权要件 |
| TAX_ADMIN_LAW | 税收征收管理法 | 15 | 征管程序 |
| COMPANY_LAW | 公司法 | 15 | 2024 新法 |
| **合计** | **5 部** | **99** | **100% verified** |

**结构性短板**：
1. 税制只有"征管法"，缺**实体税法**（增值税/企业所得/个人所得）——而这恰是本项目最核心的差异化卖点（用户具备税务师资质 + "增值税进项税抵扣审核"实务系列）。
2. 民法典 26 条只覆盖总则/个别合同/侵权，缺**物权编、合同分编、婚姻家庭编、继承编**等高引用度编章。
3. 刑法 27 条集中在总则，缺**分则高频罪名**（诈骗、职务侵占、非国家工作人员受贿等合规高频）。
4. 程序法/行政法**完全空白**（民诉、行政处罚、行政诉讼）——法律 QA 场景高频。

---

## 二、扩容原则（不可妥协的门禁）

1. **KB 100% 现行法、100% verified**：新节点必须进入 `verifications.json` 台账并由专家签名；`test_kb_integrity` 强制零 `unverified` 节点。
2. **失效法不"复活"为节点**：婚姻法/继承法/物权法等已吸收进《民法典》，**不做成独立 law**，只在 `DEPRECATED_LAW_NAMES`（10 条）保留时序陷阱。扩容只加**现行法**条文。
3. **来源唯一且可追溯**：条文只从 `flk.npc.gov.cn` **粘贴**（绝不手打）进 `SEED`；每个节点带 `source_url` + `source_accessed_at`。
4. **二元评测红利**：每多一个已核验节点 = 多一块"模型无法靠记忆蒙混"的判定面。覆盖面越广，基准越难被刷分，可信度越高。
5. **领域标签**：每个节点带 `domain`（civil / criminal / admin / tax / ip），支撑 `score.py` 的分域 HR。

## 四、为何覆盖面直接等于"可信度"

- 二元评测（EXACT=1.0 / 其余=0）下，**模型无法靠少量高频条文的记忆拿高分**；
  判定面越广，靠"背考点"蒙混的模型 HR 越真实偏高。
- 分域 HR 让招聘方/研究者看到模型在 **tax / ip / criminal** 等细分域的短板——
  这正是你"律师+税务师+专利代理师"复合背景能讲出的独特故事。
- 100% verified 是底线：任何 `unverified` 节点都会触发 `UNVERIFIED_GT` 门禁、
  被排除出判分面，等于"自废武功"降低覆盖面。扩容必须同步走签名台账。

## 五、逐法执行协议（防漂移标准动作）

每落地一部新法，严格按序：

1. **登记索引**：`laws_index.json` 增 law 条目（`name`/`aliases`/`type`/`order`/
   `issuing_authority`/`jurisdiction`/`status`/`effective_date`/`source_url`/
   `source_accessed_at`）。**不写 `deprecated_aliases`**（单源不变量）。
2. **登记来源**：`build_statute.py` 的 `LAW_SOURCES` 增 `law_code → flk.npc.gov.cn` 链接。
3. **粘贴条文**：把官方条文**粘贴**进 `SEED`（绝不手打；`effective_date` 必须与现行版本一致，
   近施行法如增值税法用 `2026-01-01`）。
4. **生成 + 校验**：
   `python -S -m knowledge_base.build_statute build` → `... validate`。
5. **专家签名**：`python -S -m knowledge_base.verify_kb` 走查 → 写入 `verifications.json`
   （每节点 `verified`）。这是唯一能把节点翻转为 verified 的动作。
6. **测试同步**：`tests/test_kb_coverage.py` 抬高 `MIN_TOTAL` / `MIN_NODES[law_code]`；
   必要时补该法的覆盖断言；全量 `python -S -m unittest discover` 保持绿灯。
7. **报告刷新**：`python -S -m benchmark.run --offline` 重生成审计报告 + 排行榜。
8. **提交**：commit（KB 变更与基准代码变更分开 commit 便于审阅）。
